# Changelog

All notable changes to @lousho/build-ai-agent will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

This section lists what is on `main` and not yet on npm.

### Added
- MCP stdio servers: new `cwd`, `stderr` (`'forward'` default, `'capture'`, `'inherit'`, `'ignore'`) and `connectTimeoutMs` (also on HTTP entries) on an `mcpServers` entry, and `McpConnections.reconnect()` reopens servers after `close()`. See [MCP](docs/mcp.md#use-mcp-servers-in-an-agent).
- MCP servers: `tools: { include?, exclude? }` on an `mcpServers` entry (and `loadMcpTools(client, name, { tools })`) loads only some of a server's tools, by their MCP names; an `include` name the server does not offer is logged. An `approval` function now gets the call's `args` (`({ name, annotations, args }) => boolean`) and runs per call, so a meta-tool like `execute({ operation })` can be gated by its arguments (the loaded descriptor's `needsApproval` is then a predicate, not a boolean). See [MCP](docs/mcp.md#tool-names-and-filtering).
- `OpenAIProvider({ api: 'chat' })` calls the Chat Completions API (`/v1/chat/completions`) instead of the Responses API, so OpenAI-compatible servers that only implement Chat Completions (llama.cpp's `llama-server`, vLLM, Ollama's `/v1`, Groq, DeepSeek, ...) work with `baseURL`. The default stays `'responses'`. With `'chat'` the built-in hosted tools (`webSearch()`, `codeInterpreter()`, `fileSearch()`) are refused with `LOUSHO_HOSTED_TOOL_UNSUPPORTED` (`hostedTool()` still passes through) and `reasoning` sends the effort without the Responses-only summary. New docs section [Local and OpenAI-compatible servers](docs/providers.md#local-and-openai-compatible-servers) covers LM Studio, Ollama, vLLM and llama.cpp, the `openai/<model>` + `OPENAI_BASE_URL` route, `fromAiSdk()`, the dummy key and setting the context window.
- `lousho doctor` shows `OPENAI_BASE_URL` when it is set (credentials and query stripped), and the new `--ping` flag calls `GET <base>/models` on each configured provider (OpenAI or the `OPENAI_BASE_URL` server, Anthropic, OpenRouter) with a 5 s timeout, warning when the server is unreachable or rejects the key. Keys are never printed.
- Structured output: `result.outputRepaired` is `true` when `object` came from the repair step. A repair can change values to make them validate (a refinement such as `total = subtotal + tax` may make the model rewrite a printed total), so check business rules on `result.object` after extraction. See [Structured output](docs/structured-output.md#repaired-output-and-business-rules).
- Structured output: `output` accepts `{ schema, promptSchema: false }` (on `createAgent()` and `ExecuteOptions`). The JSON Schema is then sent only on `responseFormat`, not also inside the system prompt - for a provider that enforces it, that stops paying ~1k prompt tokens a call on a large schema. Keep the default (a bare `output: schema`) when the provider treats `responseFormat` as a JSON-mode hint only. See [The schema in the prompt](docs/structured-output.md#the-schema-in-the-prompt).
- `send()` / `stream()` take `parentSpanId`: the run's `invoke_agent` span becomes a child of that span (e.g. the one a `withSpan()` callback gets), so several runs of a pipeline land in one trace and their cost rolls up into your span. See [Observability](docs/observability.md#span-tree).
- `githubChannel({ pullRequestOpened: true })` starts a turn on `pull_request.opened` webhooks (same signature verification, human-author and `triggers` rules as comments), so PR-review bots no longer need a parallel `webhookChannel`. See [Channels](docs/channels.md#github).
- `defineMemory({ itemSchema })` types a slot's `remember_<name>` input (any Standard Schema — zod 3/4): the parsed value is stored as canonical JSON in `text` and as `metadata`, so structured companion/state memory validates at the tool boundary. New export `memoryKey(slot, ctx)` returns a slot's storage key (`<name>#<scope>`) for seeding/inspecting provider items from code. Memory `add()` now dedupes identical `text` per scope key across all built-in providers (in-memory, file, sqlite, KV, vector). See [Memory](docs/memory.md).
- `createAgent({ modelSettings })` sets the sampling options of every model call: `maxTokens`, `temperature`, `topP`, `frequencyPenalty`, `presencePenalty`, `stop` and `seed`. A `send()` / `stream()` call can pass its own `modelSettings`, which win key by key. Sub-agents and handoff targets use their own. Agent directories accept the same `modelSettings` key in `agent.json` (the Cloudflare Worker target too). New exported type `ModelSettings`. See [Model settings](docs/configuration.md#model-settings).
- Agent directories: new `agent.*` config keys `permissionMode`, `permissions` (a serializable rule form: `tool` is a name, a list or - in a code config - a `RegExp`; `when` narrows the rule with a record of argument names to matchers - a regular expression string or an operator object (`eq`/`ne`, `lt`/`lte`/`gt`/`gte` on `Number(arg)`, `matches`), or a predicate in a code config; `action` is `allow` / `ask` / `deny`), `compaction`, `limits`, plus `hooks` and `approve`, each a path (relative to the directory) to a file default-exporting the hook(s) / the approver function, or the value inline in a code config. `instructions/<family>.md` appends to `instructions.md` when the resolved model id contains `<family>` (e.g. `openai`, `anthropic`). `lousho build --target=node-server` (and `--target=docker`) bundles a root `hooks.*` / `approve.*` file next to the config and resolves the compiled `.js` sibling; the Cloudflare Worker target carries `permissionMode`, `permissions`, `compaction` and `limits` over and accepts `hooks` / `approve` from a code config (a file path is refused, a Worker cannot import it). See [Agent directories](docs/agent-directories.md).
- Registry: a new item `type` `kit` is a whole agent directory - its `files` may sit at any (still safe) relative path - so `lousho add <kit> --dir <target>` installs `agent.*`, `instructions.md`, tools, skills and sub-agents in one item, under one permission manifest, and records it in `lousho-registry.json` like any other item. The default registry's first kit is `coding-kit`, a port of the `examples/coding-harness` baseline: workspace tools with checkpoint rewind, an allow-listed shell, permission rules, a loop guard and output cap as hooks, a compaction setting, a `fix-failing-test` skill and a read-only `explorer` sub-agent (manifest: `exec`, `fs-write`; install with `lousho add coding-kit --dir <dir> --yes --allow exec,fs-write`). See [Registry](docs/registry.md).
- The `pi` provider (H2): `createAgent({ model: 'pi/<pi-provider>/<model>' })` routes calls through `@earendil-works/pi-ai` (`1.0.3`, a new optional peer - `npm install @earendil-works/pi-ai@1.0.3`), the engine `pi-coding-agent` runs on, so pi's whole catalog (OpenRouter, Anthropic, OpenAI, Google, ...) is usable natively; e.g. `pi/openrouter/openai/gpt-4o-mini` is OpenRouter's `openai/gpt-4o-mini` (nested slashes are kept: the segment after `pi/` is the pi provider, the rest the model id). Messages (including reasoning blocks, tool calls/results and image parts), tool `parameters` (raw JSON Schema, zod 3/4 or Standard Schema), streamed chunks and usage/cost map to the same surface the `ai`-SDK providers expose, and pi's own retries are pinned off so `retry`/`fallbackModels` stay the only retry layer. Credentials are per nested provider: pi reads each one's own env var (`pi/openrouter/...` reads `OPENROUTER_API_KEY`), and a missing one fails the call with `LOUSHO_PROVIDER_MISSING_API_KEY` naming it; a missing package fails with `MissingPeerDependencyError` naming `npm install @earendil-works/pi-ai@1.0.3`. New export `PiProvider` (+ `PiProviderConfig`, whose `models` injects custom/faux catalog entries). `pi` is Node-only: the `cloudflare-worker` target refuses `pi/...` specs. See docs/providers.md#the-pi-provider.
- `piAgent()` (Build Harness 3, "pi-coder"): a Pi coding-agent session (`@earendil-works/pi-coding-agent`, a new optional peer) usable in-process as a `createAgent({ subagents })` entry - `subagents: { coder: piAgent({ cwd, model, description, permissions }) }`. Each `task` call is one Pi session under the task's `sessionId`, so `taskId` resumes and approval resumes reopen the same JSONL transcript even across a restart. `permissions` (the same `PermissionRule`s as `createAgent()`) gate every Pi tool call through a `tool_call` extension handler: `deny` refuses it, `ask` pauses the lead run durably for approval when the caller can pause and refuses it otherwise; approving re-issues that exact call once (Pi has no run-blocked-call API, so a decision prompt asks the model to repeat it and the gate lets that one call through), rejecting sends the note as the next turn. Pi usage rolls into the lead's `result.usage`, and aborts propagate to the Pi session. Node-only: the package is loaded lazily, so a consumer without it still typechecks and `run()` fails with `LOUSHO_PEER_MISSING`. Also new: `defineRemoteSubagent(impl)` wraps any `RemoteSubagent` implementation (same contract as `remoteAgent()`), and `SubagentApprovalPause` is exported for such adapters.
- Agent directories: three more `agent.*` config keys wire the approval surface. `approvalTtlMs` is `createAgent`'s run-level default for how long a pause for approval stays decidable (milliseconds); a `permissions` `ask` rule may set `ttlMs`, bounding that rule's pauses and winning over `approvalTtlMs` (both positive finite numbers, rejected otherwise). `store` declares a durable store so paused approvals survive restarts ("draft today, approve tomorrow"): `{ "dir": "./.lousho" }` (resolved against the agent directory, staying inside it) becomes a `fileStore()` - sessions, checkpoints and approvals as JSON files, with `historyLimit` / `tokenKey` also declarable; a code config may set an `AgentStore` instance instead. `store` is Node-only: the Cloudflare Worker target rejects it. `loadAgentDir(dir, { approve: null })` / `{ hooks: null }` strip the directory's wiring (the file the config names is not even imported), where `undefined` keeps it. The generated node-server / docker server keeps a config-declared `store` unless `LOUSHO_STORE` is set. See [Agent directories](docs/agent-directories.md).
- Agent directories: `"engine": "pi"` in a `subagents/<name>/` config makes that directory a `piAgent()` coding sub-agent instead of a nested `createAgent()` one - it lands in the parent's `subagents` map (the `task` tool) and its sessions run in the parent's directory, the workspace both share. Its `model` is the usual `pi/<provider>/<model>` id and its `permissions` gate the Pi session's own tool calls; the remaining config keys are ignored (Pi carries its own prompt and tools). `loadAgentDir()`'s new `piAgent` override injects `PiAgentOptions` into every such sub-agent (a faux `modelRuntime` in tests, a `sessionDir` for durable approvals); the directory always wins `cwd`, `name` and `description`. Cloudflare Worker targets reject `engine` - Pi needs the Node runtime. The default registry's second kit, `coding-pi`, is `coding-kit` on the full Pi stack: pi-provider lead, dir-declared pi coder, same safety rails (install `--allow exec,fs-write,network,env`). See [Agent directories](docs/agent-directories.md#sub-agents).
- The `approve` callback may return `'defer'` to abstain: the call stays pending (listed by `agent.approvals.list()`, resolvable by `agent.approvals.resolve()` / `streamResolve()` / `answer()`) and the run surfaces the pause - `send()` resolves with `finishReason: 'awaiting-approval'`, as if the callback had never been asked - so an approver can decide the calls it trusts and hand the rest to a human. Note: `'defer'` is now reserved; an approval note that is exactly `'defer'` defers instead of approving. See [Deciding in code](docs/approvals.md#deciding-in-code).
- Tool-call hook contexts carry `resumedAfterApproval`: `true` only when `preToolCall` / `postToolCall` fire for the post-approval re-run of a call the run paused on (`agent.approvals.resolve()`, `resumeAfterApproval()`). Stateful hooks (loop guards, audit counters) can skip the re-fire with `if (ctx.resumedAfterApproval) return;`. See [Hooks](docs/hooks.md).
- New `ToolDescriptor.transient` marks a tool bound per run (a memory slot's `remember_*` / `recall_*` tools, bound to the run's scope keys): it is left out of the agent fingerprint, so an approval-resumed run - whose registry intentionally does not rebind them - no longer reports `tools removed` agent drift on every resolve.
- Approvals can expire. `createAgent({ approvalTtlMs })` (validated: positive finite) sets a default deadline for every pause, `send()`/`stream()` take a per-call override, a `permissions` `ask` rule may set `ttlMs` (wins over the run default), and `ExecuteOptions.approvalTtlMs` covers `AgentExecutor.execute()`; sub-agents inherit the lead's TTL unless they set their own. A pending approval past `expiresAt` resolves as denied with `'approval expired'` - enforced at decision time, so a durable-store resume (a restart, another process) can never approve a stale pause - and `list()` keeps expired entries (marked by `expiresAt`) so `resolve()` still continues the run. `approval.requested` events and `UIPendingApproval` carry `expiresAt` for UI countdowns; expiry writes an audited `deny` decision to `onPermissionDecision`. See [Approvals](docs/approvals.md).
- `llmCritique(config)`: like `llmJudge` but returns `{ score, feedback }` - one judge call, a `SCORE:`/`FEEDBACK:` prompt, graceful degradation on malformed output - so evaluator-optimizer loops get actionable revision guidance, not just a number. See [Evals](docs/evals.md).
- Testing helpers: `testToolContext(overrides?)` (`@lousho/build-ai-agent/testing`) builds a valid `ToolExecutionContext` for direct `tool.execute()` calls - `getToken`/`requireAuth` fail loudly unless stubbed - and `toolResultText(message)` (root export) unwraps a `tool` message's JSON-encoded content to its result text.
- Channels: `ChannelInbound.metadata` now reaches the run as `SendOptions.metadata` (memory scopes and `when` contexts can key on channel-supplied data; it is unauthenticated, unlike `principal`), and `webhookChannel({ principal: (body, req) => ... })` can derive the caller principal from a verified body/header - so a webhook intake (PagerDuty, Grafana) attributes the run to the alerting system. See [Channels](docs/channels.md).
- New registry kits and examples replicating the most-built agent archetypes: `inbox-triage` (channel intake → classify → draft → approval-gated send, per-sender memory, `@hourly` sweep; install `lousho add inbox-triage --allow env,fs-write`) and `incident-response` (webhook alert → diagnose → risk-tiered approvals → remediate → verify → audit timeline; install `--allow env,fs-write`); examples `deep-research` (orchestrator-workers fan-out with cited synthesis), `support-desk` (triage → `handoff()` to specialist agents), `evaluator-loop` (writer ↔ `llmCritique` revision loop) and `data-analyst` (text-to-SQL with read-only enforcement). Each runs offline on mock models and accepts `OPENROUTER_API_KEY` for a live pass.
- `claudeProject(dir)`: loads a repository's Claude-Code-conventional context into options that spread into `createAgent()` — `CLAUDE.md`/`AGENTS.md` + `.claude/rules/*.md` become `instructions`, `.claude/skills/*/SKILL.md` load through `loadSkills()` unchanged, `.claude/agents/*.md` frontmatter becomes `subagents` (frontmatter `model` selects the sub-agent's model; `provider`/`model` options are the fallback), and `.claude/scratchpad/` gets a `scratchpad` note tool (name-validated `*.md` writes). Nothing in the directory executes: markdown is read as data, and `.claude/commands`, `settings*.json` and `mcp.json` are listed on `manifest.ignored` rather than loaded. See [Claude Code projects](docs/claude-projects.md).
- `decide()`: typed answers from the OpenAI Decisions API (`POST /v1/decisions`, public beta — `gpt-6-luna` only) — `predicate` questions return a probability, `choice` returns a value plus per-option `probabilities` and `confidence`, `score` returns a rubric's probability-weighted level index, and any question may come back a `refusal`. Input is a string or messages with `input_text`/`input_image` (inline base64) parts; `apiKey` (default `OPENAI_API_KEY`), `baseURL`, `timeoutMs`, `signal` and `fetch` are overridable. It is the fast path for typed decisions (route/gate/score) — no agent turn and no generated prose — and does not go through providers or OpenRouter. See [Decisions](docs/decisions.md).
- Four new examples covering the agentic-patterns catalog: `waves` (Workers · Aggregate · Verify · Extend — bounded parallel workers, deterministic merge, a typed `{ verdict, gaps }` verifier, extension waves seeded by its gaps), `phase-pipeline` (discuss → spec → plan → implement → proof gate → report on `FlowBuilder`/`FlowExecutor`, with the implement↔check retry ladder as a `oneOf` chain), `coding-agent-workflows` (a coding agent routed by a Jev-style typed decision — `output` schema `{ route, confidence, reason }`, a confidence floor escalating low-confidence calls to the careful path), and `connectors` (MCP connectors à la Claude — runs fully offline against a mock `serveMcp` stdio server exposing `docs_*`/`slack_*` tools; README maps Google Docs, Slack, GitHub and Notion). Plus `hostinger-deploy`: build an agent with `lousho build --target=docker`, ship it to a Hostinger VPS over SSH and smoke-test `/health` + bearer auth + approval pause/resume. See [Prompting and context techniques](docs/prompting-techniques.md), [Connectors](docs/connectors.md) and [Hostinger VPS](docs/hostinger-vps.md).
- Shell tool: `allow` / `deny` accept a `CommandRule` object that controls arguments. `{ command: 'npm test' }` matches exactly `npm test`, and `{ command: 'node --test', args: (rest) => ... }` lets you validate what follows. A plain string pattern keeps its meaning (the command with any arguments); the docs now say plainly that a string pattern does not stop argument flags that write files, such as `git diff --output=../x`. `ShellProvider` gains an optional `shell` property (set by `NodeWorkspace` and `SandboxShell`), and the shell tool's description now tells the model which shell runs its commands (cmd.exe on Windows: double quotes, `%NAME%` variables). See [Workspace tools](docs/workspace-tools.md).
- `compaction.reserveOutputTokens` (also on `createCompactionHook()` and `compactMessages()`): tokens kept free for the reply, so the compaction threshold is at most `contextWindow - reserveOutputTokens`. Unset, the threshold is unchanged. See [Compaction](docs/compaction.md).
- `fireSchedule(agent, schedule, { name?, firedAt?, sessionId? })` is now exported: fire a schedule once, now (an ops "run now", a test), exactly as a tick would. `startSchedules()` takes `keepAlive: true` to keep a schedules-only script alive (the timers stay unref'd by default). See [Schedules](docs/schedules.md).
- `createAgent({ compaction: { onCompaction } })`: the object form takes `onCompaction`, so you can read each summary's text without building the hook yourself.
- `createRouteHandler()` and `createDeployedServer()` take `authorizeSession({ principal, sessionId, action })` (`action` is `'read'`, `'chat'` or `'approve'`) to stop one user reading or continuing another user's session (`403 LOUSHO_SESSION_FORBIDDEN`), and `authorizeApproval({ principal, sessionId, approval })` to say who may decide an approval (`403 LOUSHO_APPROVAL_FORBIDDEN`), e.g. supervisors only. `agent.approvals.list()` / `get()` report the approval's `sessionId`, and `AgentEvent` errors carry the error's `code`. See [Who may decide an approval](docs/auth.md#who-may-decide-an-approval).
- `lousho eval --timeout <ms>` and `defineEval({ timeoutMs })` set the time limit per eval case (`0` = none; `timeoutMs` wins). `recordReplay()` takes `rerecordHint`, the re-record instruction its mismatch errors end with. See [Time limits](docs/evals.md#time-limits).
- The built-in providers (`OpenAIProvider`, `AnthropicProvider`, `OpenRouterProvider`, `OllamaProvider`) take a `fetch` option that their model calls go through, for example one with a longer undici `headersTimeout` so a slow local model's long generation is not cut off at Node's 300-second default. See [Slow local models](docs/providers.md#slow-local-models-a-custom-fetch).
- `chat` spans of a retried model call carry `lousho.retry.count` and `lousho.retry.errors` (each failure's category and HTTP status), so a long span no longer hides its failed attempts. See [Observability](docs/observability.md).
- Structured output: when `maxSteps` runs out while the model is still calling tools, a run with `output` set now makes one last model call with no tools offered ("answer now") and validates its reply - the result carries `object` (still `finishReason: 'max-steps'`) or `outputError` (`'output-invalid'`) instead of neither. The extra call is skipped when another budget limit (tokens, cost, duration) is already spent. See [Structured output](docs/structured-output.md).

### Fixed
- Tracing: a background sub-agent's cost now rolls up into the lead's `invoke_agent` span `lousho.cost_usd` (a span that ends after its parent adds to the nearest open ancestor), and `listTraces()` / `lousho traces` report the sum of the chat spans' cost, so the cost matches the token counts and `result.usage.costUsd`. (Eve MA-F2)
- `WebhookTriggerAdapter` reads the body through the 1 MB capped reader channels use and answers `413` instead of buffering any size before auth, and a failing handler's `500` no longer echoes the internal error message (Eve DUR-F18)
- CLI: `lousho --version` / `-v` prints the version; the top-level `lousho --help` lists `doctor --ping` and `eval --timeout`; `lousho chat` and `lousho acp` name themselves (not `lousho dev:`) when the target path is missing or unsupported (Eve CLI-F8, F9, F10).
- `withRetry()` no longer sleeps for a huge `Retry-After`: a hint above `backoff.maxMs` fails the call at once with `compacted.retryAfterMs` set; `retry-after-ms` is read, and `Retry-After` is honoured on a 503 (Eve PROV-F5).
- `serveAcp` (and `lousho acp`) no longer crashes on a JSON line that is `null`, an array, a string or a number, or on a `null` `params`: it answers `-32600` (or reads `params` as `{}`) and keeps serving. (Eve TOOLS-F14)
- `githubChannel`: a `/approve` or `/deny` for an approval that is not pending (stale or made-up id) no longer posts "Approved by @x" before the failure; it is ignored silently (Eve E17 / channels F5).
- Model price lookup: `claude-haiku-4.5` (OpenRouter spelling) now finds `claude-haiku-4-5`, and a snapshot match needs a date, `-latest` or a `:tag`, so `mistral-7b-instruct` no longer resolves to `mistral`; `gpt-4o-2024-05-13` has its own price (Eve PROV-F3).
- Flows: when a `parallel` branch fails, its siblings are now aborted (no further step starts; running model/tool calls get the aborted signal) and the flow returns only after every branch settles, so tools no longer keep running and events are no longer appended to `result.events` after the failure is returned. `FlowExecutionResult` gains `usage`, the summed model usage of the run. (Eve DUR-F12 / MA-F11)
- `npm run typecheck:examples` (`tsconfig.examples.json`) type-checks `examples/` under the strict test config and runs in CI; the ten errors it found are fixed (Eve DUI-F16).
- UI remote mode (React, Vue, Svelte) now keeps the conversation: the runner generates a chat id, sends `{ input, sessionId }` with every turn and regenerates it on `reset()`; `{ url, sessionId }` resumes a stored session. Previously every browser message started a new server session (Eve CORE-F1).
- MCP tools: an object input schema with a sibling `oneOf` / `anyOf` (e.g. GitHub's required-only branches `oneOf: [{ required: ['issue_number'] }, { required: ['title'] }]`) keeps its object shape instead of collapsing to `anyOf: [{}, {}]`, which providers rejected with a 400 on every request. A tool root that still converts to a non-object becomes a passthrough object (Eve TOOLS-F4).
- Flows: each `forEach` iteration now has its own `item`/`index` variables, so two loops in `parallel` branches no longer overwrite each other's `{{item}}` across awaits (wrong arguments reached tools). The loop variables no longer leak into `result.variables` after the loop, and shadow an outer variable of the same name instead of overwriting it; other `setVariable`/`outputVariable` writes still reach the flow's variables. (Eve DUR-F1)
- A throwing `onEvent` / `onAgentEvent` listener no longer rejects `send()` / `stream()` after the run's tools already ran: each listener call is isolated, and the first error of a run is reported once with `console.warn` (Eve CORE-F2).
- `webhookChannel` authenticates requests on Fetch hosts (`mountFetchChannels`: Workers, Vercel, Bun, Deno): signed, bearer and custom auth read the channel's normalized headers instead of a Fetch `Headers` object, so correctly authenticated requests no longer all get 401 (Eve E17 / channels F2).
- `limits.maxCostUsd` and `usage.costUsd` now work for every OpenRouter model: the cost OpenRouter reports (`usage.cost`) is used in place of the price-table estimate, and a warning is logged once when `maxCostUsd` is set but a call's cost is unknown (Eve PROV-F3).
- examples/ops-pipeline: `npm run pipeline:demo` now binds `MONITOR_PORT` (8787) / `SLACK_PORT` (8788) so `pipeline:demo:trigger` works; README no longer tells you to overwrite the root `.env`; `.env.example` trimmed to variables actually read; the mock PR is logged (Eve DUI-F6).
- Image and file bytes in a paused approval (`SqliteStore`, `KVStore`) or a KV checkpoint (`KVStore`, `KVCheckpointStore`) now come back as `Uint8Array` instead of `{ "0": 137, ... }`, so a resumed run sends the model the real image. Bytes are saved as `{ "$bytes": "<base64>" }`, like the session stores. (Eve DUR-F5)
- OAuth: concurrent `ctx.getToken()` calls that need the same refresh now share one token request, and a refused refresh deletes the stored token only if it is still the one that failed (otherwise the newer token is used). With a provider that rotates refresh tokens, two parallel tool calls used to send the same single-use refresh token twice, and the refused one deleted the good new token. (Eve TOOLS-F16)
- `agent.send(msg, { sessionId })` / `agent.stream(msg, { sessionId })`: concurrent calls with one `sessionId` now run one after another (per checkpoint store, in this process) instead of both continuing the same finished checkpoint, where the last save silently dropped the other turn. (Eve DUR-F2)
- Structured output on strict endpoints (OpenAI, Anthropic): `z.discriminatedUnion`, a root `z.union`, `z.record` and `z.tuple` no longer fail with a 400, and Claude no longer answers a record with `{}`. The schema sent to the model rewrites `oneOf` to `anyOf`, wraps a non-object root as `{ result }`, sends a record as `{ key, value }[]` and a tuple as `{ _0.._n }`, and the reply is decoded back before validation; a root union with a non-object branch is accepted instead of throwing. See [Schema limits](docs/structured-output.md#schema-limits). (Eve PROV-F1, PROV-F2)
- Resolving a session-paused approval from a restarted process (or any caller that never opened the session) no longer deletes the turn: the resume binds the pause's `snapshot.sessionId` back to its session — `<id>.turn-<n>` checkpoints name session `<id>` — so the finished turn commits to the transcript instead of being discarded. Previously the tool ran, the run finished, and the transcript read empty.
- Concurrent turns on one session: a second writer over the same transcript (another process, a second `fileStore` object, racing HTTP requests) can no longer silently overwrite a finished turn — committing now verifies the transcript is unchanged since the turn started and fails with `LOUSHO_SESSION_BUSY` when it isn't (the leftover checkpoint is dropped rather than replayed over the committed transcript).
- Memory slots that resolve to the same scope key no longer share one item bucket: the provider key is now `<slot name>#<scope key>`, so two `defineMemory` slots on `scope: 'global'` (or one scope function) stay separate. Items stored under the old bare scope key are orphaned (no migration).
- `createShellTool` `allow` string prefixes no longer accept workspace-escaping arguments: a command matched only by a string pattern is refused when it carries a `..` segment (including `--flag=../x`), a `~` path, or an absolute path (`/x`, `C:\x`, `\\share`). `CommandRule` and anchored `RegExp` patterns are unaffected — they are the documented escape hatches.
- `compactProviderError` surfaces the upstream provider's own message: OpenRouter's `"Provider returned error"` now carries the nested `metadata.raw` reason (bounded), so e.g. a strict-`response_format` rejection names the real schema problem.
- Finished session turns keep their checkpoint history (`<sessionId>.turn-<n>`), so `agent.fork('<id>.turn-<n>', { fromStep })` can branch a completed `session.send()` turn exactly like a finished `send(msg, { sessionId })` run.
- `webhookChannel` pause replies now include the computed `approvalPrompt` text instead of an empty `text` field.
- Registry receipt enforcement now covers a kit's sub-agents. Tools in an installed kit's `subagents/<name>/` directories (e.g. `coding-kit`'s `explorer`) were never confined, because only the top-level directory's receipt was read. They are now held to the kit's receipt like its other tools: an `exec` kit's sub-agent tools wait for approval, and the sub-agent's own `approve` file may not decide them. The `approve` callback you pass to `loadAgentDir(dir, { approve })` decides them. Without one the delegated call does not run, and the lead gets a message that the sub-agent stopped for an approval instead of an empty answer.
- A client that disconnects mid-turn no longer loses the turn. Before, closing the tab while a tool ran (a refund) aborted the turn and dropped it from the session, although the refund had happened, so the next message started with no record of it. `createRouteHandler()`, `createDeployedServer()` and the Worker now let a session turn run to its end and save it when its client goes away (`POST /chat`, approval decisions and the `useChat` endpoint), and stop writing to the closed stream. New options: `onDisconnect: 'abort'` keeps the old behaviour, and `waitUntil` keeps a serverless function alive until the turn is saved (the agent-directory Worker passes `ctx.waitUntil`). A session turn aborted with `signal` (or by leaving the `for await` loop) now keeps the tool calls that ran and their results in the transcript instead of dropping them. See [Next.js](docs/nextjs.md#routes) and [Sessions](docs/sessions.md).
- `lousho add` works out of the box again. The default registry host `registry.lousho.com` does not resolve yet, so every `lousho add` without `--registry` failed with `LOUSHO_REGISTRY_UNREACHABLE`; when the default host is unreachable it now reads the same `registry/dist/` from the repository's `main` branch on GitHub. An explicit `--registry` or `LOUSHO_REGISTRY` never falls back, and when both are down the error names both and suggests `--registry <path>`.
- `lousho add` in a non-interactive shell checks `--yes` and `--allow` before printing anything, and fails with one line naming the exact flags the item needs (e.g. `pass --yes --allow exec,fs-write`) instead of printing the whole manifest first and then asking for one flag at a time.
- `loadAgentDir()` / `resolveAgentDir()`: a file that fails to import now throws an `SDKError` with code `LOUSHO_AGENT_DIR_INVALID` instead of a bare `Error`. When a package import cannot be resolved (a kit installed into a folder with no `node_modules` above it), the hint names the package, says Node resolves it from `node_modules` next to the file or in a parent folder, and gives the `npm install` command.
- `lousho doctor` shows the base URL from `OPENAI_BASE_URL` / `ANTHROPIC_BASE_URL` on the provider's line when it is set, so a local or OpenAI-compatible endpoint is visible (credentials and query string are left out).
- Tool-call arguments that are not valid JSON no longer run the tool with `{}`: a truncated `{"path":"src"` used to make `list_dir` list the workspace root. The model now gets a `ToolArgumentsValidationError` (`LOUSHO_TOOL_ARGS_INVALID`) saying `arguments are not valid JSON: <parse error>; received: <raw text>`, and can retry. Before failing, a small repair is tried: a surrounding markdown code fence, trailing commas and double-encoded JSON are fixed when the result is an object. Empty arguments still mean `{}`. `tool.start` has a new `rawArgs` field with the text the model sent, set when it was repaired or did not parse.
- A tool name with a prefix some models add (`functions.read_file`, `tools.read_file`, `default_api.read_file`) now runs the registered tool when the rest of the name is a known tool. A tool-not-found error suggests the closest registered name and lists the available tools: `Tool 'read-file' not found. Did you mean 'read_file'? Available tools: ...`.
- Structured output: a near-miss final reply no longer costs a repair call. When the reply is not JSON as a whole, `<think>` blocks are removed and the first fenced block or balanced JSON object/array that validates is used, so a prose prefix, trailing prose after a fenced block, or a reasoning block before the JSON is accepted as is.
- Structured output: when the model answers with the JSON Schema itself, the repair message now says so and shows an example object of the expected shape, instead of listing missing fields (models repeated the schema).
- Structured output: a root-level union of objects (`z.union`, `z.discriminatedUnion`) is sent with `type: 'object'`; a root union with a non-object branch, and a zod 4 `z.date()` field (sent as `{}`, never valid), now throw a `ConfigurationError` from `createAgent()` / `AgentExecutor.execute()` that names the fix (`z.object({ result: z.union([...]) })`; `z.iso.date()`, `z.iso.datetime()`, or `z.iso.datetime().pipe(z.coerce.date())`).
- `execute_tool` spans: the deprecated `error` attribute now holds the tool's error message, like on every other span, instead of `true`/`false`, and is absent when the tool succeeded. `error.type` and the span's error status are unchanged.
- `agent.approvals.get(id)` with a `fileStore()` returns `undefined` for an id that could not name an approval file (`'bogus id!'`, `''`), as documented for unknown ids, instead of throwing `ConfigurationError`. Saving or resolving with such an id still throws.
- Retries no longer stack. A provider instance passed to `createAgent()` kept the `ai` SDK's hidden 2 retries inside every SDK retry: `retry: false` still sent 3 requests and `retry: { maxRetries: 3 }` sent 12. `withRetry()` (and so `retry`) is now the only retry layer: the built-in providers send its calls with the `ai` SDK's own retries off, and `retry: false` sends each call once. A provider instance with no `retry` set keeps its `ai` SDK retries (default 2) as before.
- A streamed model step that fails before any output is now retried. Agents stream their model calls whenever they have an event listener, and the stream was committed at its first chunk, so LM Studio's empty `reasoning-end` followed by a 500 error event was never retried. Reasoning chunks and empty text deltas no longer commit a stream; a failure after text, a tool call or the finish is still not retried. In an agent run the failed attempt's reasoning ends with `reasoning.done` before the `provider.retry` event, and the result's `reasoning` is the successful attempt's only. See [Provider retries and fallback](docs/configuration.md#provider-retries-and-fallback).
- A model call no longer sends `temperature` or `maxTokens` as explicit `undefined` when neither is set. Before, a wrapping provider that added its own `maxTokens` to the request had it overwritten. Keys that are not set are now left out.
- `loadAgentDir()` / `resolveAgentDir()` no longer silently drop `createAgent()` overrides. Only a hand-picked list (`provider`, `tools`, `permissions`, `maxSteps`, ...) reached the agent before; `guardrails`, `onEvent`, `retry`, `reasoning`, `redactContent`, `output`, `fallbackModels`, `handoffs` and the rest were ignored, so a guardrail passed this way never ran. Every override is now forwarded and wins over the directory's config. See [Agent directories](docs/agent-directories.md#overrides).
- Shell tool: under cmd.exe, `%` (variable expansion) and `^` (escape) now count as shell operators for `allow` string patterns, so `node --test %COMSPEC%` no longer passes as `node --test`.
- Provider errors from local runtimes are classified correctly. A llama.cpp / LM Studio context overflow ("request (N tokens) exceeds the available context size (M tokens)", `exceed_context_size_error`, "Context size has been exceeded") is now `context-length-exceeded` and not retryable, whether it comes back as a 400, a 500 or a stream error event, so it is no longer retried as a transient 5xx. A refused or failed connection now names the cause and URL (`connection refused (ECONNREFUSED) at http://localhost:1234/v1/responses - is the server running?`, also `ENOTFOUND`, `ECONNRESET` and undici's headers timeout) and is `timeout`/retryable. An object-valued stream error no longer reads `[object Object]`, and when the provider's error body could not be parsed (message just `Bad Request`) a short snippet of the body is appended. See [Errors](docs/errors.md#lousho_provider_request_failed).
- Handoffs now work on local models (Qwen, Llama and Mistral chat templates in LM Studio, llama.cpp, vLLM, Ollama) and on Anthropic: model requests never carry a `system` message after the conversation has started. The handoff's routing note (and any system message a caller puts mid-history) is appended to the request's leading system prompt; the transcript still records the note where it happened, so `handoffFilters` and `inputFilter`s see it as before. Previously every handoff failed with "System message must be at the beginning". See [Handoffs](docs/handoffs.md#input-filters).
- Memory stays on after a handoff: the lead's `memory` slots now follow the run to the handoff target, both in the handoff run and in every later session turn the target runs. The target gets the recalled `<memory>` blocks in its system prompt and the `remember_<name>` / `recall_<name>` tools, bound to the same scope keys (the same customer, user or session). A target's own `memory` option is still not used, and `createAgent()` now warns about it like the other run-level options. See [Handoffs](docs/handoffs.md#what-switches-and-what-stays).
- Compaction and tool search now log a one-time `console.warn` when they fall back to a 128,000-token context window for a model the registry does not know (most local models), naming `compaction.contextWindow` / `toolSearch.contextWindow` and `registerModel()`. Before, a local model with an 8K window silently never compacted. See [Local and unknown models](docs/compaction.md#local-and-unknown-models).
- The compaction hook's size estimate now counts the tool definitions and the output schema, not just the messages, and adds whatever the provider's reported prompt tokens exceeded the estimate by on the previous call. Before, an agent with many tools could overflow its window without compaction firing. `compaction.start` / `compaction.done` token counts are now these request sizes.
- MCP tool calls now honour the run's abort signal: aborting a run cancels the call in flight instead of waiting for the server to answer. A new `timeoutMs` on an `mcpServers` entry (and `loadMcpTools(client, name, { timeoutMs })`) bounds each call; the default stays the MCP SDK's 60 seconds. See [MCP](docs/mcp.md).
- An MCP tool result made only of text no longer reaches the model twice. It was serialized as both `text` and `content[].text`, which more than doubled the tool message (a 9.7k-character result became 21k). The model now gets `{ "text": ... }`; the result object still exposes `content` (non-enumerable) for code that reads it.
- Schedules no longer swallow unfinished prompt turns: a turn ending with any `finishReason` other than `'stop'` (for example `'awaiting-approval'`, whose pending approval id the message names, or `'output-invalid'`) is reported to `startSchedules()`'s `onError`, logged by a Worker's `scheduled()`, and rejects `fireSchedule()`, as the new `LOUSHO_SCHEDULE_RUN_INCOMPLETE` error.
- `startSchedules().stop()` now returns a promise that resolves once the runs in flight have finished, so shutdown can wait for them; calling it without `await` still works.
- Compaction: a rejected summary no longer turns summarizing off for the rest of the run. The hook prunes until the transcript has twice as many messages as at the rejection, then lets the summarizer try again.
- Compaction: the summarizer's model call now counts in the run. Its tokens are in `result.usage` (`byModel`, `modelCalls`), it gets a `chat` span tagged `lousho.call.purpose: 'compaction'`, and it counts toward `limits` budgets. New `GenerateHookContext.generate()` lets any `preGenerate` hook make such a counted side call.
- `compaction.done.strategy` now matches `compaction.start.strategy` (the strategy that ran). A new `appliedStrategy` (also on `onCompaction`'s info) names the result that was applied when it differs, e.g. `'prune-tool-results'` after a rejected summary.
- Two requests that decide the same approval at once: the loser now gets `409 LOUSHO_APPROVAL_CONFLICT` instead of a `200` stream that ends in an error.
- `lousho eval` no longer fails live, `--record` and `--drift` cases on vitest's 5 s default test timeout: the generated config now gives each case 10 minutes (`--replay` keeps vitest's default; a `--config` keeps its own `testTimeout` unless `--timeout` is given). A case that times out is reported as an error naming the limit.
- `lousho eval` JUnit and JSON reports are no longer empty when vitest itself fails: a timed-out case, an eval file that fails to load or a failing plain `test()` each get an `<error>` testcase, so CI never shows a crashed run as green.
- `lousho eval --record` no longer lets two cases share one cassette and silently overwrite each other. Cassette names now end in a short hash of the full case label (`<case>-<hash>.json`), so labels that only differ after 45 characters get their own file, and two cases that would still collide (the same label twice) fail at record time. Cassettes under the old `<case>.json` name still replay; the next `--record` writes the new name.
- The re-record hints of `lousho eval` (missing cassette, replay mismatch) now name `npx lousho eval --record` with the `--config` the run used, instead of `LOUSHO_RECORD=1`, which `lousho eval` ignores.
- Re-recording a cassette whose exchanges did not change keeps its `recordedAt` and `sdkVersion`, so the file shows no diff.
- Flows can be cancelled: `FlowExecutionContext` has a new `signal`. It is checked before every step, so once it is aborted no further step starts and the flow fails with the signal's reason; a running `llmCall` gets it as the request's `signal`, and a `toolCall` as the tool's `ctx.abortSignal`. A signal passed before was ignored and the flow ran to the end. Steps without an `id` now get ids unique within the run (`step-1`, `step-2`, ...); they all got `step-${Date.now()}` before, so ids collided and step events could not be paired. See [Flows](docs/flows.md#cancelling-a-flow).
- `recordReplay` now records and replays a `generate()` call's reasoning blocks and the full token usage (cached-input and reasoning tokens, provider-reported cost); before, a replayed run lost its reasoning and those counts. Existing cassettes still replay.
- The judge score parser reads `Score: 0.9`, `**0.9**`, `9/10`, `7 out of 10`, `85%` and bare whole numbers out of 10 or 100 (`8` is 0.8). Before, the first two scored 0 and `9/10` only reached 1 by clamping.
- Registering an agent's tools in another order no longer breaks replay with a mismatch pointing at `tools[0].description`: tools are matched by name, also against cassettes recorded before.
- Parallel tool calls that finish behind a slower earlier call are now checkpointed as soon as they settle, keyed by `toolCallId`. Previously only the in-order prefix of finished calls was checkpointed, so a crash while an earlier call was still running made `resume()` re-execute every finished call behind it — side-effecting tools (charges, emails) ran twice. The transcript still records results in the model's call order.

### Security
- OAuth token owners are namespaced by the authenticator (`issuer: 'authenticator:<name>'`) when a principal has no issuer, so the same id from Slack and GitHub no longer shares a token. Tokens stored under the old key are not read across authenticators; docs/oauth.md has the one-time move. (Eve TOOLS-F15)
- `createShellTool` `allow` string patterns no longer let a command read outside the workspace through shell syntax: a path is checked after quotes (and, under sh, backslash escapes) are removed, so `cat "../secret.txt"`, `cat '..'/secret.txt` and `type "c:\windows\win.ini"` are refused, as is a glob that can expand to `..` (`cat .?/x`). A command with `$`, `{` or `}` (`cat $HOME/.gitconfig`, `cat ${IFS}../x`, `cat {..,x}/secret.txt`) is refused too. Use a `CommandRule` or an anchored RegExp to allow such arguments. (Eve TOOLS-F1)
- `telegramChannel` and `teamsChannel` no longer post an OAuth sign-in link in a group chat or channel, where any member could open it and bind their own account to the user who asked. In a group they post "please sign in from a private chat with me"; the link is sent only in a 1:1 chat (as GitHub already withholds it) (Eve TOOLS-F3). See docs/oauth.md.
- Tracing: `redactContent` now defaults to `true`, so the deprecated `input`, `prompt`, `args` and `result` span attributes are off by default and `fileTraceExporter()` no longer writes prompts, system instructions and tool output to `.lousho/traces` unless you pass `redactContent: false` (or `captureContent: true` for the `gen_ai.*` content). (Eve MA-F4)
- OAuth: the `[REDACTED]` safety net for tokens a tool got from `ctx.getToken()` now also covers a thrown error (message, stack, `cause` chain), object keys, `URL` and class instances (the result is checked in its JSON form) and base64/base64url encodings of the token, such as a `Basic` header. Before, only strings, arrays and plain objects in the returned value were scrubbed. (Eve TOOLS-F2)
- Registry: the approval an install receipt enforces for an `exec: true` or `needsApproval: true` item (and for an unattested one) can no longer be waived from inside the agent directory. Before, an `allow` permission rule, `permissionMode: 'acceptEdits'` or the directory's own `approve` file - all shipped in the same untrusted directory - let its tools run without asking. Now such a call always pauses: rules and modes may still deny it, the directory's `approve` file defers it, and only a person (`agent.approvals.resolve()`) or an `approve` callback passed in code (`loadAgentDir(dir, { approve })`) decides it. `lousho add` now also says an `exec` item's tools ask for approval, instead of "its tools run without asking". See [Registry](docs/registry.md).
- The session routes no longer let a decision reach an approval of another session: `POST /chat/:sessionId/approvals/:id` answers `404` unless the approval belongs to `:sessionId`. By default, only the caller the paused run acts for may decide it, so an authenticated user can no longer decide another user's approval. If another caller (a lead, a supervisor) decides approvals over HTTP, allow them with `authorizeApproval`.
- The session routes (`createRouteHandler()`, the deployed node server and Worker) no longer send raw error text to clients. An `error` event, a failed request's `500` and `provider.retry` / `provider.fallback` events carry the error's `name` and `code` with a generic message, and the full error is logged with `console.error`. Pass `exposeErrors: true` to keep the old behavior; `lousho dev` does.
- Flows: a `toolCall` step no longer runs a tool the agent would not. It used to call the tool directly, so a `needsApproval` tool (a payment, say) ran with no approval. The step now passes the same gate as an agent's tool call: `permissions`, `permissionMode` and `onPermissionDecision` (new `FlowExecutionContext` options) apply, and a call that needs approval is decided by the new `approve` option, which has the same shape as `createAgent({ approve })`. Without `approve`, or when it returns `false` or `'defer'` (a flow cannot pause), the step fails with the new `LOUSHO_FLOW_TOOL_DENIED` code and the tool is not run. The step's arguments are also validated against the tool's input schema, as in an agent run: arguments that do not match fail the step with `LOUSHO_TOOL_ARGS_INVALID`, and the tool gets the parsed arguments (defaults applied, unknown keys stripped). A flow's declared `inputs` are now enforced too: a missing required input, or one of the wrong type, fails the flow with `LOUSHO_VALIDATION_FAILED` before any step runs. See [Flows](docs/flows.md#tool-calls).

### Changed
- A user file part (e.g. a PDF) that the provider cannot send now rejects the call with the new error code `LOUSHO_UNSUPPORTED_CONTENT` instead of being replaced by a `[file ... not sent]` text note, so a model never answers (or, under fallback, invents an invoice) without the file it was given. Under `withFallback()` / `fallbackModels` the next provider gets the call. To keep the old note, set `unsupportedFiles: 'text-note'` in the built-in providers' config or in `fromAiSdk(model, { unsupportedFiles })`. The `pi` provider is unchanged. See [Multimodal input](docs/providers.md#multimodal-input).
- Pruned tool results now leave a stub that names the call and its arguments: `[pruned: search({"query":"deploy"}) result, 18234 chars; already read]` (arguments past 120 characters are cut), instead of `[pruned: search result, 18234 chars]`. Small models stop re-issuing the same calls to see results again. Markers in the old form are still recognized.
- `judge.model` (on `defineEval({ judge })`) and `llmJudge()` / `llmCritique()`'s `model` are optional: without one the judge runs on its provider's own model.

### Fixed
- `withFallback()` (and `fallbackModels`) kept one shared "active provider" for all calls, so concurrent calls reported wrong `onFallback` / `provider.fallback` transitions, could send the fallback's model id to the primary, and booked usage and cost of calls the fallback served under the primary's model (a 16x cost under-report in the audit repro). Fallback state is now per call; the wrapper's `name` and `defaultModel` are always the first provider's, and each result (and stream) carries the new `servedBy: { provider, model }`, under which the run books that call's `usage.byModel` and `costUsd`.
- `createAgent({ output })` with an optional field (`.optional()`, `.default()`) no longer fails with HTTP 400 on OpenAI-strict structured-output endpoints (OpenAI, OpenRouter): the JSON Schema sent to the model now lists every property in `required` and makes each optional one nullable, at every level (nested objects, array items, union branches), for zod 3 and zod 4. A `null` the model returns for such a field is read back as an absent key before validation, so your `.optional()` schema still validates and `result.object` has no key for it; fields that accept `null` themselves (`.nullable()`, `.nullish()`) keep it. See [Structured output](docs/structured-output.md#optional-fields).
- MCP tool names are now valid for every provider. A `<server>__<tool>` name with characters outside `[a-zA-Z0-9_-]` (dots, spaces, slashes) has them replaced by `_`, a name over 64 characters is shortened with a hash, and collisions get a numeric suffix. Calls still reach the server under the tool's own name, kept in `metadata.mcp.tool`. Names that were already valid are unchanged.
- Registry `coding-kit` / `coding-pi`: the agent can no longer rewrite its own configuration. Their workspace is the agent directory, so before this fix `edit_file approve.ts` could replace the kit's approver. The file tools now refuse writes to `agent.*`, `approve.*`, `hooks.*`, `instructions*`, `lousho-registry.json`, `.lousho/`, `tools/`, `skills/`, `subagents/`, `.git/` and `node_modules/`. The shell allowlist drops `git diff` (`--output` could write outside the project) and accepts `node --test` only with test file paths, not flags. The loop guard now counts repeats in the current turn of the conversation instead of per process (so separate runs and agents never share counts, and a pause for approval does not reset them), never counts `node --test`, and skips the post-approval re-fire, so the kit's own "run the tests before and after every change" no longer gets blocked on the third run. Reinstall the kit (`lousho add coding-kit --overwrite`) to pick this up.
- A stdio MCP server that fails to start now says why. A missing command, an npm 404 or an exit code 3 all used to surface as `MCP error -32000: Connection closed`. They now throw `McpStartError` (`LOUSHO_MCP_START_FAILED`) with `exitCode`/`signal` and the last 20 stderr lines in `stderr` and in the message, and a server that never answers fails after `connectTimeoutMs` instead of hanging. A failed or timed-out start no longer leaves the process running. Behaviour change: `connectMcp()` rethrows this coded error instead of wrapping it in `connectMcp: MCP server '<name>' failed to connect: ...`. See [LOUSHO_MCP_START_FAILED](docs/errors.md#lousho_mcp_start_failed).
- `agent.ready()` after `agent.close()` reconnects the agent's MCP servers; it used to return the closed connections.

## [1.0.0-rc.0] - 2026-10-04

The first 1.0 release candidate. Upgrading from a `1.0.0-alpha.*` release?
Read the [upgrade guide](docs/upgrading.md): imports moved to subpaths, dead
and superseded APIs were removed, and the patch guardrails are now patch
checks. What 1.0 considers public is defined there (every `exports` entry and
the checked-in `api/` reports).

### Breaking
- Flows, the Jira / GitHub / Slack / email tools, encryption, `StorageService` and the validators moved out of the package root (A1). Import them from their subpath: `FlowBuilder`, `FlowExecutor`, `validateFlow` and every flow type (`AgentFlow`, `EditorStep`, `FlowExecutionEvent`, ...) from `@lousho/build-ai-agent/flows`; `createJiraTools`, `createGitHubTools`, `createSlackTool`, `slackTool`, `postSlackAlert`, `createEmailTool` and their types from `@lousho/build-ai-agent/integrations`; `EncryptionUtils`, `DTOEncryptionFilter`, `DecryptionError`, `sha256`, `generatePassword`, `StorageService`, `StorageServiceApprovalStore`, `LocalStorageCheckpointStore` and the validators (`validateWithSchema`, `safeValidate`, `isValidEmail`, ...) from `@lousho/build-ai-agent/utils`. The integrations are no longer in `@lousho/build-ai-agent/tools` and the flow types are no longer in `@lousho/build-ai-agent/types`. Nothing else changed: the classes and functions are the same. For file-backed stores with `createAgent()`, prefer `fileStore(dir)`.
- Removed `AgentType`, `AgentTypeDescriptor`, `AgentConfig.agentType`, `AgentBuilder.setType()` and the agent-type registry (`agentTypesRegistry`, `getAgentTypeDescriptor`, `getAllAgentTypeDescriptors`, `isValidAgentType`, `validateAgentConfig`, `validateAgentTools`). They had no runtime effect since 1.0.0-alpha: delete the `setType(...)` call and the `agentType` field. Also removed, because nothing implemented or used them: the repository interfaces (`IRepository`, `IAgentRepository`, `ISessionRepository`, `IResultRepository`, `SessionData`, `ResultData`, `SDKRepositories`), `DataLoadingStatus`, `PaginationParams`, `PaginatedResponse`, `DeepPartial`, `Timestamped`, `IdEntity`, `AgentExecutionOptions`, `AgentExecutionResult`, `AgentDefinition` and `ToolSetting`. If your code used one of these types, copy its declaration into your project. A checkpoint saved with `agentType` still loads; the field is ignored.
- Removed `ExecuteOptions.onEvent` and the `ExecutionEvent` / `ExecutionEventType` types, deprecated since LOU-D41. Pass `onAgentEvent` to `AgentExecutor.execute()` / `stream()` / `resumeAfterApproval()` instead (with `createAgent()`, `onEvent` already receives `AgentEvent`s and is unchanged). The mapping from the old event names to `AgentEvent` types is in docs/streaming.md#listening-without-iterating ("Migrating from `onEvent` / `ExecutionEvent`"). The one-time "onEvent is deprecated" warning is gone with it.
- Removed `createDelegateTool()`, `DelegateAgentOptions`, `DelegateAgentResult` and `DelegationDepthExceededError`. Use the `subagents` option instead, on `createAgent()` or `AgentExecutor.execute()`: create the child with `createAgent({ provider, instructions, description })` and pass `subagents: { billing }`. ### Security
- `openApiTools()` can refuse private destinations (#291): with the new option `privateAddresses: 'refuse'` (default `'allow'`, unchanged), every operation request and the document fetch, each redirect hop included, fails when its host is or resolves to a loopback, link-local, private or reserved address. Host names go through the pinned DNS lookup `http_request` and `web_fetch` use (one resolution per connection, every address checked, the socket connects to the checked address), so DNS rebinding cannot reach a private address; IP literals in every form `URL` normalizes (decimal, octal, hex, IPv4-mapped IPv6) and `localhost` / `*.localhost` are refused when the tools are made. `allowPrivate` lists hosts that may be private. `'refuse'` cannot be combined with a custom `fetch` (it throws a `ConfigurationError`: a custom fetch's connections cannot be pinned) and needs Node.js (`undici`, `node:dns`); where undici cannot load, making the tools throws a `ConfigurationError`. See docs/openapi-tools.md#security-rules.
- The registry permission manifest is now enforced when an agent directory loads and runs (#272, follow-up to M7a). `loadAgentDir` re-hashes every file the `lousho-registry.json` receipt lists; an item with edited or missing files is reported `unattested` (a warning naming the item and files, and `manifest.registry` on `resolveAgentDir()`, which also gains the new `Attestation`, `RegistryItemStatus` and `RegistryStatus` types) without refusing the load. Every tool a receipt item owns then runs inside the manifest accepted at install: an `exec: true` or `needsApproval: true` item's tools - and any unattested item's tools - always wait for approval (a tool's own `deny` still denies); `fetch` while the tool runs is limited to the declared `network` hosts; `process.env` shows only the declared `env` names; and a `requiresSandbox` tool gets a narrowed adapter (`run()` refused without `exec`, `writeFile()` without `filesystem: "write"`, a command env of the non-secret base plus the declared variables only). The envelope stays as narrow as the last accepted manifest until `lousho add <name> --overwrite` attests the current files. Limits, unchanged: the guards intercept `fetch` and `process.env`, not `http`/`net`/`axios`, the filesystem, module-scope captures or a container's own network policy; the manifest is still not a sandbox. See docs/registry.md#permission-manifest.
- `http_request` is no longer open to DNS rebinding (N13a). It resolved a host name once to check it against the private-address list and then let `fetch` resolve it again to connect, so a name that answered a public address to the check and `127.0.0.1` (or a cloud metadata or intranet address) to the connection reached the private address; the docs and a comment in the Worker runtime described the check as rebinding-safe. Now the one resolution is the check: the in-process path connects through an undici `Agent` whose `connect.lookup` checks every address and hands the socket the address it checked (each redirect hop included), and the sandboxed path (`sandboxExecute`, which agents use) resolves and checks the host in the agent's process and has the sandboxed process connect to that address (node:http/https with a fixed lookup; the host name still goes in `Host` and TLS SNI). The private-address list is now the shared one (below), which adds `0.0.0.0/8`, `100.64.0.0/10`, `192.0.0.0/24`, `198.18.0.0/15`, multicast and reserved `224.0.0.0/3`, `::`, `ff00::/8`, NAT64 `64:ff9b::/96` and 6to4 `2002::/16` to what `http_request` refused. Behavior changes: a host name that cannot be resolved now fails with the resolver's error instead of being passed to `fetch`; `undici` is loaded on the first `http_request` request (not only with `validateSSL: false`). New option `createHttpTool({ allowPrivate })` for hosts that may resolve to private addresses. Cloudflare Workers have no DNS hook, so neither tool exists in the Worker build; docs/deployment.md now says what a Worker can and cannot check.
- A run's principal is fixed for the whole run (N10b, #250): an approval resolved by another caller, a restart, `agent.resume()` or a session's pending turn continue as the caller that started the run, and the decider is recorded as the approver (`ctx.approval.by`), never swapped in as the run's principal, so a later caller cannot use an earlier caller's grant by approving their pending call. The principal comes only from route auth or a channel's verified sender; the approvals route and channels never read it from a body field. It is frozen before a tool, a policy or a hook sees it. Remote sub-agents are not told who the caller is.

- Local traces and `lousho traces` (M5a): `createAgent({ exporter, captureContent })` traces every run of the agent (`send()`, `stream()`, session turns, `agent.resume()` and runs continued by `agent.approvals.resolve()`; sub-agents join the lead's trace). ### Fixed

- A channel button click (Slack, Discord), inline-keyboard tap (Telegram), Adaptive Card press (Teams) or `/approve` command (GitHub) after a restart is now bound to the conversation's session before the approval is resolved, so its continuation is appended to the session transcript again (#279). The decision names the conversation it came from (`inbound`); with checkpointed sessions (`mountChannels` `store` with `checkpoints`, e.g. a `SqliteStore`) it is accepted only when that session's pending turn waits on exactly that approval id and kind - a decision for another conversation, a replay of a decided one and a decision of the wrong kind are refused (`LOUSHO_APPROVAL_NOT_FOUND`) before the approval is touched, and `onDecision` audits only decisions that pass, so a replayed click cannot run the tool twice and the thread's next message continues the same session. Without a checkpoint store nothing can be checked, so the approval store alone decides, as before.
- A channel's function `approvers` works after a restart (#280): `ctx.approval(id)` asked only this process's `agent.approvals.list()`, so a pause the restarted process did not make looked the same as a denial and the function failed closed. `ApprovalStore` gains an optional `load(id)` - `resolve()` without removing the record; every shipped store implements it, and a custom store without it keeps compiling and behaves as before - and the new `agent.approvals.get(id)` reads through it. `ctx.approval` falls back to that, so the function sees the same request (`toolName`, `input`, `sessionId`, `principal`) it saw before the restart and fails closed only when no store knows the id (a process-local approval store still forgets its pauses at a restart).
- A hand-written Cloudflare Worker can now bundle `createAgent` (#289). The package root also exports file stores, the agent-directory loader, MCP over stdio and sandboxes, so bundling it for `platform: 'browser'` failed with `Could not resolve "async_hooks"` (and `crypto`, `fs/promises`, `http`, `net`, `stream`) - only the generated Worker ever bundled, because `lousho build --target=cloudflare-worker` redirects those imports to shims itself. `@lousho/build-ai-agent/worker` is a new subpath exporting `createAgent` (and its config types), `memoryStore`, the KV stores (`KVStore`, `KVCheckpointStore`, `CHECKPOINT_KV_BINDING`), the schedule helpers (`defineSchedule`, `handleScheduled`), `serveFetch` (the `/chat` API as a fetch handler), the providers a Worker can run and the whole Worker-safe subset agent-directory code may import. The SDK's own build produces it through the same Node-builtin/sandbox/QuickJS shims the adapter applies (plus new `ollama-ai-provider` and `@modelcontextprotocol/sdk` ones, which an external specifier would leave unresolvable and `mcpServers` therefore fails on first connect - use `lousho build` for MCP on Workers), so the published entry carries no `node:` import for a user's own bundler to fail on; `ai`, `zod`, `@opentelemetry/api` and the `@ai-sdk/*` provider packages stay external specifiers resolved from the user's install. Guarded by `src/deploy/worker.test.ts`; see docs/cloudflare-workers.md#writing-your-own-worker.
- The published `.d.ts` files no longer import the types of optional peers (#346): `SubprocessSandboxOptions.dockerOptions` is now the structural `DockerConnectionOptions` (same fields as dockerode's `DockerOptions`, passed through unchanged) and `McpClientLike` is the structural subset of the MCP SDK's `Client` it already was (`listTools` / `callTool`). Before, `dist/index.d.ts` imported `dockerode` and the shared schema chunk imported `@modelcontextprotocol/sdk`, so a consumer compiling with `skipLibCheck: false` without those optional peers installed got TS2307 inside the SDK's own declarations. A dockerode `DockerOptions` or MCP `Client` value still satisfies both types.
- `lousho` CLI surface (LOU-R19): `lousho dev`/`lousho chat --traces` now writes traces for a `.ts`/`.js` module that exports an already-built `createAgent()` agent - the module's export could not take the flag's exporter after the fact, so nothing was written. `createAgent()` remembers the config it was built with (readable via the internal `createAgentConfigOf()`), and the loader rebuilds the agent with the flag's exporter (the module's own `exporter` is replaced while the flag is set; a module exporting an agent not made by `createAgent()` prints a warning and keeps its own). A spec path that does not exist (e.g. `lousho chat missing.yaml`) now fails with the coded `LOUSHO_SPEC_NOT_FOUND` instead of a raw ENOENT. `lousho add --dry-run` no longer fails when a target file already exists; it prints the file list with an "(exists - a real install needs --overwrite)" marker and exits 0 (the symlink checks still run). Top-level `lousho --help` lists the implemented flags again: `--no-schedules`/`--traces` on `dev` and `chat`, `eval`'s record/replay/drift/`--config` flags, `init`'s `--sdk-path`, and `build`'s positional form.
- A cassette failure keeps its type through `agent.send()` (LOU-R13): a replay mismatch (or a missing cassette raised by the provider-interception seam that `lousho eval` installs) was compacted into a generic `CompactedLLMProviderError`, losing the cassette path, the call number and the re-record hint. `CassetteMismatchError` is now an `SDKError` with code `LOUSHO_CASSETTE_INVALID` (docs/errors.md already claimed cassette errors carry it), and the run loop rethrows cassette errors untouched instead of compacting them, so `send()` rejects with the `CassetteMismatchError` itself (`.cassette`, `.callNumber`). `setProviderInterceptor()` and the `ProviderInterceptor` type are now exported from `@lousho/build-ai-agent/testing`, the public entry for the model-boundary seam docs/evals.md describes.
- A tool call approved with `agent.approvals.resolve()` (or `resumeAfterApproval()`) now has its `execute_tool` span (#281). It ran before the continued run started, outside any span, so OpenTelemetry and `fileTraceExporter()` showed the continued run's `invoke_agent` and `chat` spans but not the approved tool. The continued run's `invoke_agent` span now opens first and the approved call runs inside it: its `execute_tool` span is a child of it (a `run_code` call's inner calls and a sub-agent the tool starts are children of the tool span), with the same `captureContent` / `redactContent` rules as any tool span, and no span is made for a rejected call. A pause that happens again (sign-in) leaves the `invoke_agent` span with the tool span and no `chat`.
- A tool that returns `undefined` (or an async generator that yields nothing) no longer writes a `tool` message with `content: undefined` into the transcript (#341). Its result is now `null` everywhere: the transcript and the next model request carry `"null"`, and `tool.done`, approval resumes, `run_code` and flows see `null`. Providers, session stores and checkpoints get a valid string.
- `recordReplay` matches a tool's parameter schema the same way under zod 3 and zod 4 (#333). A zod 4 schema was fingerprinted from its JSON Schema (with `$schema`, `required`, `additionalProperties`) while a zod 3 one, and so every recorded cassette, used a fingerprint of the schema itself, so cassettes recorded with zod 3 failed to replay with zod 4 installed (the CI `peers` jobs `ai4-zod4`, `ai6-zod4` and `ai7-zod4` failed on every replay test). Both now give the same fingerprint for the same schema; existing cassettes stay valid and need no re-recording, and a real change to a tool's parameters still fails the match.
- Parallel `task` calls now get their `taskId`s, and background tasks start, in call order: allocating an id awaited a SHA-256 digest whose completion order is not fixed, so with `maxConcurrent: 1` the second task could take the slot first (#296, the flaky "queues tasks beyond maxConcurrent" test).
- `SubprocessSandbox.run()` no longer fails with HTTP 404 "no such container" for a command that exits at once (#326): the container is `AutoRemove`d, and `wait()` was only called after `start()`, so a fast command could be gone by then (10 of 40 parallel `true` runs failed on Docker Desktop). It now begins `wait({ condition: 'next-exit' })` before `start()`, and removes the container if `start()` itself fails.
- The `cloudflare-worker` build's Node-builtin leak check now accepts the runtime-guarded `loadNodeModule("node:module" | "node:dns")` probes that `@ai-sdk/provider-utils` 4 (installed with `ai` 6) uses, as it already did for `ai` 7's `loadBuiltinModule`; without it a Worker bundle built on `ai` 6 failed with "Node builtins leaked" (found by the new `ai6` matrix entries).
- `isAgentEvent()` is now exhaustive (the runtime type list is a `Record<AgentEventType, true>`, so the compiler rejects a missing type). It had no `agent.drift`, so remote UI clients (`parseEventStream()`, the React, Vue and Svelte bindings) silently dropped that event.
- A remote sub-agent's token usage is added to the lead's `result.usage` (M10b). It was dropped, so budgets and cost reports undercounted delegation to a `remoteAgent()`. The lead adds what the remote agent reports on its `run.done` event to its totals, to `usage.delegated` and to `byModel['remote:<name>']`, which keeps the remote's own `costUsd` (the lead's `costUsd` is `undefined` when the remote sends none). A remote run that pauses for an approval adds what it spent up to the pause, and the continuation adds only what it spent after it; background remote tasks roll up the same way. A deployment that sends no usage adds nothing. `RemoteRunOptions` has a new optional `onUsage(usage)` callback; `RemoteSubagent.run()` still returns `Promise<string>`, so hand-written ones compile unchanged. See docs/sub-agents.md#remote-sub-agents.
- `lousho studio` finds the Agent Forge build that ships inside the installed package when it is run from a project that does not have `apps/agent-forge` (it used to fail with "could not find apps/agent-forge" everywhere except the SDK repo). A project's own `apps/agent-forge` still wins, and `.lousho/` is still created in the directory you ran it from. `--dev` from an installed package still needs the TypeScript source and says so.
- Documentation corrections: install commands, CLI command lists, optional peers, durable execution and compaction descriptions, the Status section, reasoning and file-part notes in the providers guide, and the `KVStore` note in the deployment guide now match the code. Ticket ids are gone from user-facing prose.

- One tool-error shape (LOU-U14): every failed tool call reaches the model as `{ error, toolName, message, kind }` (message capped at 2,000 characters, transcript message flagged `isError`), whichever path failed: `kind` is `'execution'`, `'validation'` (plus `issues`), `'not-found'`, `'rejected'` (plus `note`), `'not-run'`, `'mcp'` or `'sandbox'`. New exports `toolErrorResult()`, `ToolErrorResult`, `ToolErrorKind` and `ToolErrorInput`; `McpToolError` and the sandbox guard's error (named `SandboxRequiredError`, not exported) carry a `toolErrorKind`. `kind` is additive on thrown-error and validation results. The paths that built their own shapes changed, see Changed. See docs/tools.md.
- Background sub-agents end with the lead run (LOU-Y4.2): when a run ends (any `finishReason`, or an error), its background sub-agents still queued or running are cancelled, and the run resolves once their runs have stopped, so none of their events reaches `onEvent` afterwards. `withSubagentOptions(subagents, { awaitBackgroundOnFinish: true })` waits for them instead (an aborted or failed lead still cancels them). The new `result.backgroundTasks` lists the run's background tasks as `{ taskId, agent, status, elapsedMs, ... }` (absent when it started none). `createAgent({ subagentOptions: { maxConcurrent, awaitBackgroundOnFinish } })` sets the same options (over any attached with `withSubagentOptions()`, without changing the `subagents` value). The executor hook behind it is public: `ExecuteOptions.onRunEnd({ result } | { error })` is called exactly once per `execute()` / `stream()` run, however it ends; an error it throws rejects the run. See docs/sub-agents.md.
- Durable sessions (LOU-W9): `agent.session({ id, store, checkpointStore })` (or a `store` that carries both, `{ sessions, checkpoints }`, such as a `SqliteStore`) runs each turn with `sessionId: '<id>.turn-<n>'` and that `CheckpointStore`, so it is checkpointed after every model response and tool result. `session.resume()` finishes a turn interrupted by a crash, a failed checkpoint write or a `PropagatingToolError` (also in a new process) without re-running recorded tool calls or model responses, adds it to the transcript as `send()` would and returns its result (`null` when nothing is pending); `session.pending()` reports an unfinished turn and `session.discardPending()` drops it. `send()` / `stream()` resume a pending turn before sending the new message. A turn paused for approval stays in its checkpoint until it finishes: `resume()` / `send()` throw `SessionAwaitingApprovalError`, and `agent.approvals.resolve()` continues it in the session. Sessions without a checkpoint store are unchanged. See docs/sessions.md.
- Structured output (LOU-V4): `createAgent({ output: zodSchema })` (and `ExecuteOptions.output`) makes the final reply a JSON object validated by the schema. `send()`, `run.result` and `agent.approvals.resolve()` resolve with it as `result.object`, typed `z.output<typeof schema>` from `send()` and `stream()` of `createAgent()` agents (`SimpleAgent`, `AgentRun` and `ExecutionResult` gain a type parameter that defaults to `unknown`); `result.text` keeps the raw JSON. The system prompt gets an `## Output format` section with the schema as JSON Schema, and each model call carries the new `GenerateOptions.responseFormat: { type: 'json', schema? }` hint, which the `ai`-SDK providers map to `experimental_output` JSON mode. The reply is parsed (a code fence is tolerated) and validated; when invalid, one repair step sends the model the issues (it counts against `maxSteps`), and a reply still invalid ends the run with the new `finishReason: 'output-invalid'`, no `object` and `outputError: { message, issues }`. `run.done` gains an optional `object` field (additive: the event schema version stays 1). See docs/structured-output.md.
- Background sub-agents (LOU-Y4): the `task` tool takes `background: true`, which starts the sub-agent and returns `{ taskId, status: 'running', agent }` at once. Agents with `subagents` also get `agent_status({ taskId? })` (`queued`/`running`/`done`/`failed`/`cancelled`/`awaiting-approval`, plus `elapsedMs`), `agent_await({ taskId | taskIds, timeoutMs? })` (the synchronous `task` result, or `status: 'timeout'`) and `agent_cancel({ taskId })`. `withSubagentOptions(subagents, { maxConcurrent })` bounds how many run at once per lead run (default 3; the rest queue). Background sub-agents inherit the lead run's runtime and `maxSubagentDepth`, and aborting the lead cancels them. Not yet: resuming one that paused for approval (it reports `awaiting-approval` with its `approvalId`). A user tool named `agent_status`, `agent_await` or `agent_cancel` now conflicts with `subagents`, like `task`. See docs/sub-agents.md.
- React hook (LOU-D15): new `@lousho/build-ai-agent/react` subpath with `useLoushoAgent(source, options?)`. `source` is `{ agent, sessionId? }` (in process, via `agent.stream()` or `agent.session({ id }).stream()`) or `{ url, headers?, fetch? }` (POSTs `{ input }` and reads the SSE or NDJSON event stream). It returns `messages` (text and tool calls with status, args and result), `status` (`idle`/`streaming`/`awaiting-approval`/`error`), `pendingApproval`, `error`, `usage`, `lastEvent`, `send()`, `stop()` (aborts; unmount aborts too), `approve(note?)` and `reject(note?)` (via `agent.approvals.resolve()` in process, or `POST ${approvalsUrl}/${id}` remotely). The framework-neutral `reduceAgentEvents()` reducer and `parseEventStream()` parser are exported from the same subpath. `react` (`^18 || ^19`) is an optional peer dependency. See docs/react.md.
- Summarizing compaction (LOU-W3): `summarizeStrategy({ model, protectedTokens?, prompt?, maxSummaryTokens? })` replaces the turns before the protected tail with one `[Conversation summary]` user message written by `model` (an `LLMProvider` or a `"provider/model"` spec), keeping system and pinned messages and each assistant turn together with its tool results; if the summary call fails it falls back to pruning and reports `error`. `twoPhaseStrategy()` (the recommended strategy) prunes first and summarizes only when still above the threshold. `pinMessage()` / `isPinned()` and the new optional `Message.metadata` (never sent to providers) mark messages no built-in strategy compacts. `CompactionStrategy.compact()` may now be async, so `compactMessages()` returns a Promise; `CompactionResult` / `CompactionInfo` gain `summary` and `error`, and `CompactionInput` gains `thresholdTokens` and `signal`. A strategy that throws no longer fails the run: the hook reports the `error` to `onCompaction`. See docs/compaction.md.
- `createAgent({ retry, fallbackModels })` (LOU-V7.2): `retry` (`withRetry()` options, or `false`) retries failed model calls and defaults to `{ maxRetries: 2 }` for models given as `provider/model` strings (or picked from the environment); a `provider` instance is wrapped only when `retry` is set. `fallbackModels` are `provider/model` strings tried in order once the primary model's retries are used up (`withFallback([withRetry(primary), withRetry(fallback), ...])`). `agent.stream()`, `session.stream()` and `AgentExecutor.stream()` report them as two new typed events, `provider.retry` (`attempt`, `maxRetries`, `delayMs`, `error: { message, category? }`, `provider`) and `provider.fallback` (`from`, `to`, `error: { message }`), for any `withRetry()` / `withFallback()` provider. Additive: the event schema version stays 1.
- Context compaction (LOU-W2): `createCompactionHook()` returns an `AgentHook` that, before a model call estimated above `thresholdPercent` (default 0.9) of the model's context window, replaces tool results older than the newest `protectedTokens` (default 40,000) with a `[pruned: <tool> result, N chars]` marker, in the run's transcript itself. `compactMessages()` compacts a conversation by hand; `CompactionStrategy` / `pruneToolResultsStrategy()` make the strategy pluggable. See docs/compaction.md.
- `AgentSpec.mcpServers` (LOU-D20): a validated map of MCP servers (stdio `command`/`args`/`env` or HTTP `url`/`headers`) in agent spec files. `loadSpec()` reports a bad entry with its name, `lousho doctor` reads the validated field instead of the raw file, and `specToAgent()` exposes the parsed servers as `agent.mcpServers` (connecting them is TODO(LOU-D20.2)). Existing specs are unaffected.
- `createAgent()` agents can pause for approval (LOU-D21): a `needsApproval` tool no longer fails the run with "requires approval but no approvalStore". The run pauses (`finishReason: 'awaiting-approval'`) in a per-agent `InMemoryApprovalStore` (or the new `approvalStore` option), and `agent.approvals.list()` / `agent.approvals.resolve({ id, approved, note? })` continue it, in its session if it paused in one. The `approve` option decides calls in code without pausing.
- Tools own their contract (LOU-D22): `ToolDescriptor` gains optional `inputSchema` (zod) and `execute(args, ctx)`, which are now the canonical fields. `defineTool()` sets both and no longer calls `ai`'s `tool()`. Argument validation, the schema sent to the model, and tool execution read them first and fall back to `tool.parameters` / `tool.execute`. `ToolDescriptor.tool` (the `ai` v4 `Tool`) is now legacy: it is still built by `defineTool()` and still accepted on hand-written descriptors this release, but new code should set `inputSchema` and `execute`.

### Deprecated
- `ExecuteOptions.onEvent`, `ExecutionEvent` and `ExecutionEventType` (LOU-D41). `onEvent` keeps working: the executor now emits only `AgentEvent`s, and an adapter derives the old events from them in the old order (`start`, `text-complete`, `tool-call`, `tool-result`, `error`, `abort`, `finish`, sub-agents' tagged with `subagent`), with a one-time `console.warn`. Differences: `finish` now comes after the run's checkpoint is written (it was just before), and a run that fails outside a step (an input guardrail that throws, `onRunEnd` throwing) now gets an `error` event too. Migration: replace `onEvent` with `onAgentEvent` (or `createAgent({ onEvent })`); `start` -> `run.start`, `text-complete` -> `text.done` (step usage on `step.done`), `tool-call` -> `tool.start`, `tool-result` -> `tool.done` / `tool.error`, `abort` / `finish` -> `run.done` (`finishReason`), `error` -> `error` (`{ name, message }`). The full table is in docs/streaming.md#migrating-from-onevent--executionevent.
